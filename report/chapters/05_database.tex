\chapter{Database Trail}\label{ch:db}

Every request leaves a permanent row that records what was decided, when, by which model and how
confidently. In the Compose stack this is PostgreSQL, which handles concurrent writes and keeps its
data in a named volume. For local runs and unit tests I use SQLite. The code is the same in both
cases because it goes through SQLAlchemy; only \texttt{DATABASE\_URL} changes.

\file{app/db.py} creates the engine once at start-up, with a retry loop in case the database is
still starting, and creates the table if it does not exist. In \texttt{/predict}, once the model
has answered, one row is inserted in its own transaction (\texttt{Session.begin()} commits, or rolls
back on an error) and the browser is redirected to \texttt{/result/<id>}. That page reads the row
back from the database, so if the result page shows up, the record exists. Rejected uploads and
model failures get a row too, so the trail has every attempt, including the failed ones.

\texttt{/history} lists the newest records first, 20 per page, with totals per verdict, filters for
AI-generated and Real, and a toggle that shows the rejected uploads. \texttt{/api/history} returns
the same rows as JSON.
